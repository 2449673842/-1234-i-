# SciFigure 知识产权与内容保护方案

**文档更新时间：2026-07-12 14:24:55 +08:00**

> 本文是产品与研发管理建议，不替代中国执业律师、专利代理师或软件著作权代理机构的正式法律意见。

## 1. 结论

建议申请软件著作权，但不要把软著当作唯一保护手段。

```text
软件著作权：保护源代码和软件表达，便于形成权属与版本证据
商标：保护 SciFigure Studio 名称、中文名称和标识
专利评估：保护满足新颖性、创造性和实用性的技术方案
商业秘密：保护不适合公开的算法、规则、映射和运维实现
合同与制度：约束员工、外包、合作方和用户的权利义务
研发证据：证明代码、文档、版本和设计形成的时间与作者
```

## 2. 软件著作权

### 2.1 是否应该申请

建议在核心版本稳定、主要模块名称和权属明确后申请第一版软著。后续出现重要架构或产品版本时，可根据需要登记新版本。

软著登记通常具有以下价值：

- 形成软件名称、版本、权利人和完成时间的登记证据。
- 在融资、合作、招投标、上架或发生侵权争议时提供权属材料。
- 规范代码归属，避免个人、外包团队与公司之间权属不清。

### 2.2 软著不能解决什么

软著主要保护代码和界面等具体表达，不当然垄断产品想法、功能需求、算法思想或“科研图形编辑平台”这一概念。其他团队独立实现相似功能，不一定构成著作权侵权。

### 2.3 申请前准备

- 明确申请主体，避免个人与未来公司权属冲突。
- 整理软件全称、简称、版本号、完成日期和首次发表状态。
- 固化一份可构建的版本并保存 Git commit、构建产物哈希和版本说明。
- 准备符合登记要求的源程序与操作说明材料。
- 确认员工、外包和合作开发代码均有书面权属约定。

## 3. 商标与品牌

尽早检索并申请 `SciFigure Studio`、拟使用的中文名称和核心图形标识。具体类别应由商标代理结合实际业务确认，软件产品和在线软件服务通常需要重点评估相关类别。

在商标确定前：

- 保留品牌设计源文件和首次使用证据。
- 域名、社交账号和应用市场名称尽量统一占位。
- 不在未检索前投入大量品牌宣传物料。

## 4. 专利评估

如果跨语言图形内省、语义编辑意图、图元稳定身份、代码回写或局部重绘调度形成了可验证的技术效果，可让专利代理师评估是否属于可申请的技术方案。

重要规则：在完成专利评估前，不公开可能影响新颖性的核心技术细节，包括完整算法流程、关键数据结构、映射规则、性能实现和可复现技术说明。宣传页和用户帮助页只公开操作能力与必要兼容接口。

## 5. 商业秘密

以下内容默认作为内部资料管理：

```text
Python/R 图元内省与身份稳定算法
语义目标解析与批量映射规则
拖拽坐标回写和编辑 patch 编译逻辑
局部重绘、缓存、并发调度和失败恢复策略
renderer 隔离、部署拓扑和安全策略细节
真实用户数据、项目文件、诊断日志和运营数据
```

保护措施：

- 代码仓库保持私有，按角色授予最小权限。
- 生产密钥、数据库和源码仓库分离，不进入 Git。
- 员工、外包和合作方签署保密及知识产权归属协议。
- 核心模块设置 CODEOWNERS、审查规则和访问日志。
- 对导出、下载、管理员操作和异常访问保留审计记录。
- 离职或合作结束时立即回收账号、密钥和设备访问权限。

## 6. 公开内容边界

可以公开：

- 用户操作流程、支持格式、模板和常见问题。
- 用户代码正常运行所必需的数据入口和代码规范。
- 抽象的数据安全承诺和经过验证的服务能力。

不应公开：

- 图元内部标识、身份算法、语义映射和编辑编译细节。
- 可用于绕过安全边界的路径、接口、部署和防护参数。
- 主数据库结构、内部管理接口和生产凭据组织方式。
- 未申请专利且可能具有新颖性的完整技术实现。

公开 AI 提示词只包含用户代码兼容要求，不包含平台核心实现。

## 7. 用户、文档与模板权利

- 用户上传的数据和脚本权属应在用户协议中明确，平台仅获得提供服务所需的有限授权。
- 隐私政策说明数据用途、保存期限、删除、导出、备份和安全事件处理方式。
- 平台自有帮助文档、示例代码、模板数据和示例图增加版权声明及允许使用范围。
- 用户生成或外部 AI 生成代码的权利与第三方风险由用户协议明确。
- 对开源依赖建立许可证清单，遵守署名、分发和源码提供义务。

## 8. 研发证据与版本管理

- 所有正式提交保留作者、时间、评审和测试证据。
- 发布版本生成不可变 tag、源代码归档和 SHA-256 哈希。
- 保存产品需求、设计文档、原型、测试报告和上线记录。
- 重要版本定期生成只读离线备份，并验证可恢复。
- 对 AI 辅助生成代码保留人工评审和修改记录，确认最终代码权属与第三方许可风险。

## 9. 推荐执行顺序

```text
P0：确认申请主体、代码权属、私有仓库和保密协议
P1：确定软件名称与版本，准备并提交第一版软件著作权
P1：检索品牌并推进商标申请
P1：在继续公开技术细节前进行专利可行性评估
P2：完成用户协议、隐私政策、模板许可和开源许可证清单
P2：建立发布哈希、证据归档、访问审计和离职回收流程
```

## 10. 上线前检查

- 软件著作权申请主体与代码实际权属一致。
- 所有贡献者和外包代码有书面归属依据。
- 品牌完成商标检索并确定申请策略。
- 可能申请专利的技术尚未被详细公开。
- 用户协议、隐私政策和数据处理规则已由专业人士审阅。
- 公开页面没有泄露内部协议、安全参数和生产结构。
- 第三方依赖许可证清单完整。
